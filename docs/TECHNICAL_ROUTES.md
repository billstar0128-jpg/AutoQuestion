# 技术路线说明

本文讨论如何把网页或屏幕中的题目转换为可核对的参考答案，说明当前设计与可选方案，不包含完整实现或部署步骤。

**当前设计采用 DOM + 文本模型、截图 + 视觉模型两条路线，没有独立 OCR 模块。OCR + 文本模型仅作为可选路线讨论。**

## 1. 共用处理链路

| 阶段 | 要解决的问题 | 设计原则 |
| --- | --- | --- |
| 用户触发 | 什么时候开始、处理哪个目标 | 主动触发；防止连续触发产生重复任务 |
| 输入获取 | 题干、选项和题组是否完整 | 只读取授权目标；目标改变时取消本次获取 |
| 输入路由 | 哪种输入方式适合当前内容 | 区分网页语义内容与图片内容，结合模型能力选择路线 |
| 识别与推理 | 如何理解题目并组织参考答案 | 保留题组、选项与阅读顺序；避免凭空补全缺失内容 |
| 结构校验 | 返回内容能否安全、清楚地展示 | 检查字段、题型和答案对应关系；失败时明确提示 |
| 结果呈现 | 用户如何核对与使用 | 分题展示，支持选择和复制，由用户自行判断 |

Windows 端以 F8 触发当前目标处理；Android 端以悬浮窗触发截图分析。入口不同，题目与结果的表达可以保持一致。

## 2. DOM + 文本模型：利用网页语义

先从用户授权的网页中读取可见题组，提取题干、选项及其关联，再交给文本模型分析。可靠输入既包括文字，也包括“哪些选项属于哪道题”这样的结构。

这种路线适合具有清晰标题、标签、单选框或复选框语义的网页。相比只读取整页文字，它更有利于保留题组关系；但网页文字可访问，不代表题组一定能可靠提取。

主要限制包括：

- 浏览器扩展需要用户授权，操作系统热键本身不会授予网页访问权限。
- Canvas、自绘控件或图片中的文字通常不能直接作为 DOM 题目读取。
- 跨域框架、封闭的组件结构、缺失标签与歧义题组会影响获取结果。
- 读取范围应限定于当前目标与可见内容，不应把输入框中已有的答案混入题目。

当前设计只读题目，不通过 DOM 修改选项或提交页面。

## 3. 截图 + 视觉模型：直接理解画面

先捕获目标的可见区域，再由支持图片输入的模型直接完成题目识别与推理，返回按题组织的结果。当前路线没有先调用独立 OCR 再调用文本模型的步骤。

它适用于桌面窗口、PDF 阅读画面、图片题目与网页画布。能否处理图片取决于具体模型能力，不能仅凭服务商品牌判断。

Windows 端需要确认捕获对象仍是用户触发时的目标；Android 端通过 MediaProjection 获取系统屏幕共享授权，并在悬浮窗触发后处理画面。悬浮窗权限与屏幕捕获授权是不同条件。系统禁止捕获的页面可能无法得到有效图片，不能靠此路线绕过限制。

此路线的主要代价是画面质量和版面理解的不确定性：文字过小、截图不全、覆盖层、复杂公式和多栏排版都可能引起误读。截图还可能包含通知或其他私人信息，应尽量缩小到必要内容。

## 4. OCR + 文本模型：可选的拆分方案

概念上可以先用 OCR 把截图转换为文字，再重建题干、选项和题组，最后交给文本模型推理。**这是一条可选方案，不代表 AutoQuestion 已实现或提供独立 OCR 功能。**

这种拆分便于分别检查文字识别与解题环节，也可按场景选择本地或远程文字识别。但 OCR 结果通常需要额外的结构恢复，不能把一段识别文本直接视为完整题目。

选择此路线时需要评估：

- 题号、选项、表格和阅读顺序能否正确恢复。
- 公式、图形与文字之间的关系能否保留。
- OCR 误差如何传递给后续模型，以及何时要求用户重新获取输入。
- 新增识别环节带来的处理时间、资源需求和维护成本。

是否采用应由实际题目样本评估决定，不能预设其一定比视觉模型更快、更便宜或更准确。

## 5. 路由与失败处理

对浏览器题目，当前设计优先尝试可靠的 DOM 获取；桌面画面和不适合 DOM 的内容使用视觉路线。Android 当前采用截图 + 视觉模型。

自动回退应发生在**输入获取阶段**：例如页面无法形成可靠题组，且仍能确认原目标、允许截图、模型支持图片输入时，才考虑改用视觉路线。显式选择 DOM 时，获取失败应提示错误。

已经取得题目后出现的认证失败、网络超时、模型输出格式错误或答案校验失败，不应触发另一轮截图请求。这类错误需要直接反馈，避免重复发送内容和增加请求。

目标窗口、标签页或捕获条件变化时，应取消本次处理，不应自动换到另一个目标继续。

## 6. 结构化结果的作用与限度

不同路线可以使用一致的结果表达：题型、题干、选项、参考答案与简要说明。多题输入应保留顺序并分题展示；没有选项字母时保留实际选项文本，不虚构编号。

校验可以检查必填字段、答案是否对应已有选项、填空答案数量是否匹配，以及主观题与客观题字段是否混用。它无法判断知识结论、计算过程或推导是否正确，也无法保证没有漏题。

结果因此应作为待核对的参考信息。用户确认后再自行使用；整个流程不自动勾选、填写、提交或翻页。

## 7. 如何评估路线

评估时应把输入获取与答案质量分开观察：先检查题目是否完整、选项关系是否正确，再检查参考答案与说明。可分别记录漏题、误读、结构失败、推理错误和目标变化取消的情况。

样本应覆盖普通网页、图片或画布、复杂版面，以及不同题型。记录样本范围、所用路线与模型条件后再比较结果；单次演示或格式通过不能代表整体准确率，也不能推出所有网站或模型均可用。
